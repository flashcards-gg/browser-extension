# Flashcards.gg for Safari

Safari takes web extensions only inside a Mac app. This folder is that app: a
small window that says whether the extension is turned on in Safari, opens
Safari's settings, and explains the three steps. The extension itself is
`dist/safari`, built from the same sources as the other browsers.

| | |
|---|---|
| Xcode project | `FlashcardsSafari.xcodeproj` (targets *Flashcards.gg for Safari* and *Flashcards.gg for Safari Extension*) |
| Bundle IDs | `gg.flashcards.safari`, `gg.flashcards.safari.extension` |
| Minimum | macOS 12; Safari with Manifest V3 support |
| Extension resources | referenced from `../dist/safari` (not copied) — run `npm run build:safari` first |
| Languages | 30, from `App/Localizable.xcstrings`, generated by `scripts/strings.py` |

## Run locally

```bash
npm run build:safari
open safari/FlashcardsSafari.xcodeproj   # Run the "Flashcards.gg for Safari" scheme
```

Then Safari → Settings → Extensions → turn on **Flashcards.gg**. Click the
toolbar button to open the options page and paste an API key.

Against a local server instead of flashcards.gg:

```bash
FCGG_API_BASE=http://localhost:9090 npm run build:safari
```

## Texts

`App/Localizable.xcstrings` is generated — edit `scripts/strings.py` and run
`python3 safari/scripts/strings.py`. The menu item's name, the description and
"Create a key" come from `../_locales`, so the app words them exactly as the
extension does.

## Store build

```bash
safari/build-safari.sh   # → safari/build/pkg/Flashcards.gg for Safari.pkg
```

Builds `dist/safari` for production (it stops if `FCGG_API_BASE` is set),
bumps `BUILD_NUMBER`, takes the version from `package.json`, archives and exports
a Mac App Store package signed through automatic signing (`ExportOptions.plist`).
Uploading it to App Store Connect is a separate step.
